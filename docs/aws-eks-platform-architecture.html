Architecture overview

The AWS path is a dedicated EKS platform in a project VPC (10.50.0.0/16), with private worker nodes, a single cost-optimized NAT Gateway, an internet-facing Application Load Balancer reconciled by the AWS Load Balancer Controller from Kubernetes Ingress, and Argo CD inside the cluster syncing kubernetes/overlays/aws from GitHub. This environment is intentionally separate from the VMware kubeadm lab.

What Terraform provisions

  • Dedicated VPC, IGW, public/private subnets, one NAT + EIP
  • Project-scoped IAM roles (cluster, node, LB Controller)
  • EKS 1.36 + managed node group (2 × t3.medium desired)
  • Add-ons: vpc-cni, kube-proxy, coredns, eks-pod-identity-agent
  • Helm: AWS Load Balancer Controller + Argo CD
  • GitOps bootstrap (AppProject + Application)

What is intentionally absent

  • No RDS, Route 53, ACM, WAF, CloudFront, ECR
  • No second NAT Gateway (unless enable_single_nat_gateway=false)
  • No hand-managed aws_lb resource
  • No MetalLB / ingress-nginx / Calico on AWS
  • Cluster CloudWatch logging off by default
  • No Terraform ownership of app Deployment/Service/Ingress

Component notes (primary diagram)

ALB (data plane): Internet-facing Layer 7 load balancer. With target-type: ip, it forwards HTTP directly to VPC-routable pod IPs. Health checks also probe those registered pod targets.

Ingress / Service (control plane): Kubernetes Ingress is the desired-state API object. The Service is the backend reference the controller uses to discover endpoints. Neither is a runtime hop for ALB→pod traffic.

AWS Load Balancer Controller: Watches Ingress (and related objects) and reconciles AWS resources: listener, rules, target group, and registered pod IP targets.

NAT Gateway: Outbound Internet for private workers only — not inbound application access.

Security boundary: Terraform defines a project node security group allowing VPC CIDR traffic to workers (supports ALB→pod paths). Exact ALB SG IDs are controller-managed at runtime and are not hard-coded here.

Network architecture

Dedicated project VPC — never the account default VPC (172.31.0.0/16). Default: enable_single_nat_gateway = true (one NAT in public AZ-a).

Networking facts verified against modules/vpc
  • Exactly one aws_nat_gateway and one aws_eip when single-NAT mode is enabled.
  • Both private route tables point at that NAT when enable_single_nat_gateway=true.
  • Public route: 0.0.0.0/0 → Internet Gateway.
  • Subnet role tags for ELB / internal-ELB are set for AWS Load Balancer Controller discovery.

EKS architecture

Control plane is AWS-managed. Workers are EC2 instances in an EKS managed node group placed only in private subnets.

Scaling defaults: desired 2 · min 1 · max 3 · node_instance_type=t3.medium · root_volume_size=20. Workers use private subnet IDs only (node_subnet_ids = module.vpc.private_subnet_ids).

Traffic flow & Kubernetes networking

With alb.ingress.kubernetes.io/target-type: ip, runtime HTTP goes ALB → pod IP. Ingress and Service participate in control / reconciliation, not as data-plane hops. AWS VPC CNI is the underlying pod networking layer (VPC-routable IPs), not an HTTP hop. No Calico, MetalLB, or ingress-nginx on AWS.

Ingress / Service roles (control plane)

  • ingressClassName: alb — desired-state object
  • scheme: internet-facing
  • target-type: ip — ALB registers pod IPs
  • Service platform-lab:8000 — backend reference for the controller
  • Health check path /health against pod targets

NetworkPolicy (AWS)

  • Allows TCP/8000 from VPC CIDR 10.50.0.0/16
  • Aligned with ALB→pod IP traffic sourced from the VPC
  • Replaces local overlay’s ingress-nginx allow rules

GitOps architecture

Terraform installs Argo CD and bootstraps the AWS Application. Continuous reconciliation of application objects is Argo CD’s job.

IAM & API access

Project-scoped IAM / least-privilege design. Does not reuse ec2_admin_role or AdministratorAccess.

Resource ownership

Terraform provisions the platform. Argo CD manages the application layer.

Terraform owns

  • VPC, Internet Gateway
  • Public/private subnets, route tables
  • NAT Gateway, Elastic IP
  • IAM roles & policies
  • EKS cluster & managed node group
  • EKS add-ons
  • AWS Load Balancer Controller installation (Helm + Pod Identity)
  • Argo CD installation (Helm)
  • GitOps bootstrap (AppProject + Application)
  • destroy_safety helper

Argo CD owns

  • Deployment
  • Service
  • Ingress (drives ALB)
  • HPA
  • PDB
  • NetworkPolicy
  • ConfigMap
  • Application workloads under kubernetes/overlays/aws
  • ServiceMonitor — whitelisted in AppProject; not present in current AWS overlay (observability deferred)
Hard rule: Terraform and Argo CD must not manage the same Kubernetes application objects. Terraform does not create Deployment/Service/Ingress for platform-lab.

Destroy flow

Verified against null_resource.destroy_safety, scripts/pre-destroy-cleanup.sh, and module depends_on edges. Terraform destroys dependents first; destroy_safety therefore runs while the cluster API is still up.

AWS cost model

Pricing varies with AWS region, usage, traffic and current AWS price lists. Figures below are planning estimates, not guaranteed invoices.

Major fixed cost drivers (approved design)

  • EKS control plane
  • 2 × t3.medium workers
  • 40 GiB gp3 (2 × 20 GiB roots)
  • 1 NAT Gateway
  • NAT public IPv4
  • ALB (from Ingress)
  • ALB public IPv4 addresses (typically dual-AZ)

Planning estimates (incl. GST concept)

  • 24×7 operation is approximately ₹20K–₹21K/month including GST before meaningful traffic usage.
  • 48-hour continuous lab run is approximately ₹1.3K–₹1.4K including GST before meaningful variable traffic.

Variable adders: NAT GB processing, ALB LCU, internet egress, cross-AZ transfer on the single-NAT path. Cluster logging is off by default to avoid CloudWatch log charges.

Key design decisions

Cost-conscious networking

One NAT Gateway shared by both private AZs. Extensible to dual-NAT via variable without module redesign.

Security defaults

Private workers, restricted EKS API CIDRs, encrypted root volumes, IMDSv2, project-scoped IAM, Pod Identity for the LB Controller.

Clear ownership split

Platform via Terraform; application via Argo CD from kubernetes/overlays/aws. ALB is Ingress-driven, not hand-coded in Terraform.

Destroy safety

Pre-destroy cleanup removes Applications/Ingresses while the controller can still delete ALBs, avoiding orphaned cloud resources.
